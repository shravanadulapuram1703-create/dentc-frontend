DentC (Reckon Dental PMS) — End-to-End Test Workflows

Role-based, setup-to-module test playbook  ·  Document version 1.0  ·  Generated 2026-09-02 from branch feature/uat-realse-v2  ·  Standalone file: works offline, results are saved in this browser (localStorage) and can be exported below.

What this document is

A complete set of 38 ordered workflows covering every implemented module of the application. Workflows are grouped by phase and tagged by role. The core question this playbook answers is: does what we configure in Setup actually show up and get enforced in the day-to-day modules (Scheduler, Patient, Charting, Transactions, Ledger, Claims, Reports, Utilities, My Page)?

Run the phases in order. Phase 1 (Administrator foundation) creates the offices, providers, users, codes, fees, plans and clinical catalogs that every later workflow depends on. Each later step that verifies a Setup value is tagged TRACE.

How to use it

  1. Enter your name in Environment & test data; fill the Test Data Ledger as you create records (IDs are reused later).
  2. Filter by your role using the chips in the toolbar, or run everything as Administrator.
  3. For each step choose Pass / Fail / Blocked / N/A and add a note (bug ID, screenshot name, actual behaviour).
  4. Steps tagged GAP are known backend gaps: the expected result describes today's documented behaviour. Mark Pass if it behaves exactly as described, Fail if it behaves differently.
  5. Steps tagged NEGATIVE verify that something is blocked. If the app lets you through, that is a Fail.
  6. Use Export JSON at the bottom to hand results back; Print (Ctrl+P) produces a clean paper copy.

Environment & test data

Prerequisites

  • Frontend: Vite dev server on http://localhost:5173 (backend CORS only allows this origin).
  • Backend: FastAPI on http://127.0.0.1:8000 (or the Cloud Run URL set in VITE_API_BASE_URL). Some list endpoints are slow on the 61k-patient tenant (login ≈10 s, lists 5–55 s) — wait, do not double-submit.
  • Default local admin: username admin / password admin (tenant 1). Replace with the credentials issued for your environment.
  • Browser: Chrome/Edge latest, desktop width ≥ 1280px. Open DevTools → Console and Network; note any red errors in step notes.
  • Two browsers/profiles are needed for Messaging (WF-33) and for role comparison (WF-04, WF-35).
  • Optional env flags (in .env): VITE_MESSAGING_BACKEND=api (real messaging; currently blocked), VITE_APPOINTNOW_BACKEND (default local simulation), VITE_JIRA_MODE/VITE_JIRA_PROJECT_KEY=KAN.

Naming convention for test data

Prefix everything you create with QA-<initials>-<MMDD> (e.g. QA-SA-0902 Office, patient QA-SA-0902 Testpatient). This makes records easy to find and clean up, and prevents collisions between testers sharing one tenant.

Roles & what the application actually enforces

Read this before testing roles. The backend stores a single free-text role per user (catalog from GET /roles) plus security groups with rights. The frontend only enforces the six items in the table below. Everything else (security-group rights, patient access level, login-time restrictions, IP rules, assigned offices, HIPAA-compliant scheduler preference) is stored and displayed but not enforced by the UI. Any denial you observe beyond these six comes from the backend and should be recorded as such.

Known dead links & navigation defects (record, don't re-discover)

  • There is no 404 page. A mistyped URL renders a blank page inside the shell.
  • Patient icon strip: Messages, SMS/Email, Referrals, Members, Recent point at routes that do not exist (blank patient content); Websites, Print, Search RP show "Coming Soon" alerts.
  • Transactions menu: Insurance Payment, Capitation Payment, Treatment Plan (wrong path), Pre-Authorization List, Batch Patient Payment, Batch Insurance Payment have no route.
  • Utilities menu: Office Specific → Universal (6 items) and DCA (2 items) have no route.
  • /setup landing grid buttons and toggles are decorative (no navigation). Use the Setup ▾ menu.
  • Placeholder ("Coming Soon") routes: Vendor API Settings ×2, Assign Offices to Groups, Provider Per-Office Settings, Employees, Custom Demographics, CDT↔CPT↔ICD maps ×3, Custom Pick Lists, Scheduler View/Template setup, Insurance Forms (dental/medical), 10 Reports sub-reports.
  • /patient-overview and /patient-ledger redirect to hard-coded patient 12345 even when logged out.
